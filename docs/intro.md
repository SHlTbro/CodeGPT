# 一页介绍

## 它是什么

Local Codebase MCP 是一个跑在你电脑上的 MCP 服务器。ChatGPT 这类云端 AI 通过它检索、阅读、搜索你本机的代码项目：AI 问「认证流程在哪里实现」「最近改了什么」，服务器就在磁盘上找出答案，代码文件始终留在你的电脑里。

## 解决什么问题

让云端模型理解本地代码，常见的做法是打包上传。上传的 zip 是某个时刻的快照，项目继续改动，模型的理解就停在旧版本；node_modules、构建产物这些噪音还会占掉上下文；代码交出去之后，每改一次就得重传一次。

Local Codebase MCP 让模型经 MCP 协议按需读取此刻磁盘上的真实文件与 git 状态。模型能看到什么，由一张项目注册表决定，没登记的项目对它不存在。

## 为什么值得用

- **回答基于当下事实。** 项目刚改完一行，下一个提问拿到的就是新状态。
- **上下文按需供给。** `project_info`、`list_files`、`read_batch` 先建立架构认知，`read_file` 再定向深读，`search_code` 用 ripgrep 全文定位；装了语言服务器还能跳转定义、查引用、看编译诊断。
- **写入受控。** 三个写工具默认全项目关闭；开启后写文档只限配置的白名单目录（默认 `docs/`），更新必须携带读取时返回的全文哈希，文件被别人改过就拒绝写入，不会静默覆盖。
- **安全面在服务端强制。** 服务器只监听本机回环地址，公网可达性只由你部署的隧道提供；路径逃逸、敏感文件、超大返回，各有闸门。
- **部署是一条命令的事。** 双击 `deploy.bat`，装依赖、生成配置模板、探测空闲端口、启动服务和隧道、打印可粘进 ChatGPT 的地址，一次跑完。

## 它适合谁

同时维护多个本地项目、想让 ChatGPT 参与代码理解与文档整理，又不肯把整个项目打包上传的人。15 个工具（12 个只读、3 个受控写）覆盖项目发现、目录浏览、批量读取、全文搜索、git 状态与语言服务器智能。

## 设计立场

核心理念是三句话：模型负责思考，MCP 只提供事实，用户掌握决策。它不做命令执行、不做 Agent 规划、不做代码索引数据库；它只是 AI 理解真实代码的入口。
